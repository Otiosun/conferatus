## Por que esta rodada existe
As leis máximas em `AGENTS.md` exigem *preguiça inteligente*, não refazer o que funciona, código humano, testes confiáveis, regressões e honestidade de conclusão. A auditoria anterior encontrou `tests/browser_smoke.py` legado: procurava `Simular voto`, uma ação que não existe mais. Antes de qualquer nova função ou refatoração, é mais barato restaurar a confiança na jornada crítica.

**Falha reproduzida ANTES de editar o teste:** na prévia v0.10.17, `python tests/browser_smoke.py` parou em `get_by_role('button', name='Simular voto')` com `TimeoutError`, após o carregamento normal da tela. O problema foi um seletor histórico obsoleto, não uma falha do backend nem um novo defeito de voto.

## Mudança delimitada, critério de aceite e evidências
**Único arquivo de código de teste alterado:** `tests/browser_smoke.py`. Nenhum arquivo `src/`, CSS, dependência, endpoint, banco ou dado real foi alterado. Substituímos a jornada de 2026-10 pela sequência atualmente existente, sem introduzir infraestrutura de teste.

**Critério de aceite:** um único smoke que percorra as ações reais da prévia em **320, 390, 740 e 1280 px**, com nenhuma exceção JS, nenhuma quebra horizontal, e confirmação assertiva dos seguintes estados:
- Duas opções de votação FICTÍCIA; escolha da opção `o2` faz a contagem exemplificativa passar para 21 votos; seleção e reset voltam ao estado inicial.
- Menu abre e fecha com Esc, devolvendo foco ao botão de abertura.
- Busca por membro fictício, acesso ao perfil e aba de proposições.
- Deep link para outro membro fictício em novo documento, sem confundir dados de pessoas.
- Histórico de proposições acessível.
- Painel de ferramentas de TESTE abre e permite simular papel de membro comum: texto de acesso exclusivo da diretoria; ao retornar a diretor, o painel é fechado antes das ações seguintes para não interceptar eventos.
- Edição de ACDM ID de fixture e desfazer subsequente, sem alterar a base institucional.
- Calendário informa explicitamente que o botão **Iniciar uma Votação** apenas programa deliberação local; formulário abre e fecha.
- Editor de proposições acessível; nenhum overflow ou page error.

**Teste concluído:** `python tests/browser_smoke.py` PASS em quatro larguras. **Controle negativo real:** alteração temporária SOMENTE do HTML compilado, substituindo `não inicia uma votação real` por outra mensagem; o teste falhou com `AssertionError: 320` na verificação do aviso. O artefato foi restaurado integralmente e o smoke passou novamente. Este controle prova que ao menos essa regressão é detectada; não prova que todas as classes de bug possíveis são detectadas.

**Build:** `npm run build` executado em diretório isolado com compilação TypeScript, montagem de HTML offline e **18/18 testes Node** aprovados.

**Regressão completa de navegador:** **18/18 scripts Playwright `browser_*.py` aprovados** (17 anteriores + smoke modernizado), executados em grupos e individualmente para evitar o limite de tempo do ambiente. A matriz cobre calendário, virada do dia, linhas/expansão, filtros, perfil, rascunhos, revisão, Socii, vínculos, integridade de assinaturas, recuperação de JSON, IDs duplicados e esclarecimento da prévia. A maioria roda em quatro larguras; navegação testa nove. Nenhum script existente foi removido da contagem.

**Limitações declaradas:** o navegador deste ambiente bloqueia URLs locais, logo o smoke usa `page.set_content` com HTML offline e URL `about:blank?demo=1`. Não simula reload HTTP real, login, autorização no servidor, persistência compartilhada ou colaboração entre contas. As ferramentas de papel são somente demonstrativas. `npm run build` no Cloudflare não executa Playwright; aprovação do build remoto **não implica** que o navegador rodou remotamente. O `package.json` atual não fornece `lint`; TypeScript não é substituto honesto para uma análise lint inexistente.
