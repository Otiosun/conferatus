## Defeito reproduzido
- Ao recuperar `sessionStorage`, `isSavedDraft` e `isSavedSchedule` verificavam o formato mas **não a unicidade do ID entre registros**. Duas proposições com `id='p-primary'`, embora títulos/redações diferentes, apareciam lado a lado; botões `data-draft` e vínculos de programação resolvem `drafts.find(...)`, portanto apontavam para a primeira, inclusive quando a ação parecia se referir à segunda.
- Uma programação com `id='s-primary'` duplicado também podia surgir duas vezes, com cancelamento e expansão resolvidos somente por ID. Um rascunho Socii com o mesmo parceiro duas vezes permitia contar a mesma pessoa mais de uma vez.
- `tests/browser_unique_records_v0116.py` falhou **antes do patch** em 320 px: `duplicated draft ID accepted` (a segunda proposição foi indevidamente exibida). A causa foi confirmada no código, não inferida de estilo.

## Correção de escopo mínimo e não destrutiva
- `src/main.ts` agora exige parceiros com IDs distintos dentro de `isSavedDraft`. Um rascunho com o mesmo participante repetido não é aceito na visualização.
- Uma nova função `uniqueSavedRecords` percorre os registros locais, mantém **a primeira ocorrência estruturalmente válida** de cada ID de proposição/programação, e isola entradas inválidas ou repetidas em `rejected` preservando seus objetos originais. Se a primeira ocorrência está inválida e a seguinte é válida, a válida é preservada (seen só recebe IDs de itens válidos). A lista continua acessível e a mensagem explica `registros incompletos ou repetidos`.
- `saveWorkflows` continua gerando backup legado `conferatus:invalid-session-backup-v0114` sem sobrescrever seu conteúdo anterior; nova chave `conferatus:quarantined-session-backups-v0116` mantém um histórico local de lotes rejeitados, acrescentando somente lotes ainda não idênticos. Se a estrutura prévia do histórico é inválida, a gravação falha sem substituí-la. O salvamento ainda é da sessão de navegador: NÃO é backup remoto garantido.
- **Nenhuma regra de voto, número de membros, aprovação institucional, identidade, novo prazo, colaboração remota, login, API ou dependência** foi criada.
